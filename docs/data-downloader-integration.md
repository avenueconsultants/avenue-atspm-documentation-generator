# Data Downloader integration (Part 7)

The consumer integration is prepared locally on `documentation-integration` in
`_source/atspm-data-downloader`. The generator stays on
`feature/generic-documentation`. Nothing has been committed, pushed, merged or
published. The nested consumer checkout is ignored by this generator repository;
open it separately to review its Git changes. The reusable integration inputs are
retained here under `integration/data-downloader`.

## Source and coverage

Inspected source:
`opensourcetransportation/atspm-data-downloader` at commit
`51d563383e15f7b90ab2b3abb91d1b2c39aafeac` (2026-08-05).
The consumer's C# code and its build/release workflows are unchanged.

- `DownloaderConfiguration` is already annotated and bound under that exact name
  in `HostBootstrapper`. Its eight properties are all documented.
- The application folder is scanned, so newly annotated sections in new folders
  join the single Data Downloader page automatically. Tests are outside this root.
- `DownloadFormat` contributes `NdJson`, `Csv` and `Json` choices, with the source
  default `DownloadFormat.NdJson`.
- List binding uses `DownloaderConfiguration__LocationIdentifiers__0` (then `__1`,
  etc.). Examples use placeholders, including the API key and reserved example URL.
- Both structured logger classes contribute 16 unique events: 1000–1007 for
  aggregation downloads and 2000–2007 for event-log downloads. No duplicate-ID
  exceptions or fabricated IDs were needed.

The consumer README explains that property annotations and initializers are not
the complete runtime contract: `HostBootstrapper` validates an absolute API URL,
non-default ordered dates and a nonempty location list. The downloader chooses the
current directory when OutputPath is unset. The existing options table was also
corrected for indexed location variables and the runtime API URL requirement.

## Activation dependency

The shared generator changes are still uncommitted and unpublished. The caller
follows generator `main` once the shared workflow is merged there. For an
earlier branch-only run, replace its one `@main` with a pushed generator branch
or full commit SHA containing the reusable workflow.

After review, commit/push the generator development branch if testing before a
main merge. This requires changing only the caller's `uses` ref.
Commit/push the consumer's integration branch, then review the artifact and
documentation PR against
`documentation-integration`. Actions PR-creation permissions must be enabled.
Manual dispatch availability and PR checks follow the
[shared workflow instructions](shared-pr-automation.md).

This local integration proves generation and PR preparation, not hosted PR
creation or repository permission settings. Pages/wiki publishing stays deferred.

## Reproduce and verify

Build the Release generator and install `requirements.txt`. For another consumer
checkout, copy the two files in `integration/data-downloader` to the corresponding
consumer paths, add `README-section.md` to its README, and apply the two options
table corrections described above. Use the shared action or CLI to generate the
six managed output files. Keep the hidden ownership manifest in Git.

The generator's CI now checks out the pinned source and runs:

```powershell
python scripts/check_data_downloader.py --source-root _source/atspm-data-downloader
```

This command requires the pinned commit and unchanged application sources; it
allows local documentation integration changes. All mutation experiments happen
in a temporary copy. It verifies eight settings, required annotations, enum values,
indexed environment names, source links, 16 event IDs, branding and strict site
builds. It also verifies exact repeatability, revision-only PR suppression and
automatic discovery of a new required setting, a section in a new folder and a
new log event without editing the map.

The staged PR-preparation script was exercised separately against the real
consumer checkouts: the initial run proposed documents, and the next run reported
no meaningful changes. The generated files were then saved in the consumer.
Actionlint passed for its caller and the updated generator CI.

Local preview: `_generated/data-downloader-preview/site/index.html`.
The preview uses the unchanged pinned application's source revision and timestamp,
not the time this integration was prepared. The first snapshot establishes an
initial baseline and does not invent historical differences.
