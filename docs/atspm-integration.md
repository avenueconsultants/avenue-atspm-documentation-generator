## Preserved coverage

The six pages remain Config API, Data API, Identity API, Report API, Event Log
Utility and Watchdog. All assignments and example values are preserved.
Discovery finds 13 source section definitions, yielding 16 named bindings in the
reference because DatabaseConfiguration is instantiated for four contexts.
Named database environment variables retain their context prefixes.

The log reference contains 91 messages with the same eight explicitly permitted
duplicate event IDs: 201, 202, 203, 1000, 1001, 1002, 1003 and 9001. The map does
not broaden duplicate allowances or change source event IDs.

ATSPM keeps explicit service assignments. New properties in mapped sections need
no map edits. A new section within the configured roots fails coverage until its
service assignments are supplied; automatic assignment to all six services would
be misleading. The workflow intentionally leaves `sync-container` unset. Definitions
outside those roots require a map update. API documentation models and external
dependency settings retain the limitations documented in the consumer README.

Ten existing property-description warnings remain: AggregationType and Dates on
EventLogAggregateConfiguration; FileFormat, DateTimeFormat, Dates, Included,
Excluded and Path on EventLogExtractConfiguration; Website and DefaultEmailAddress
on IdentityConfiguration. These do not block generation. No summaries or runtime
requirements were invented to silence them.

## Activation and upstream migration

The caller's `@main` reference cannot execute until the shared workflow is
reviewed and merged into generator `main`. The current generator changes are
still local. For branch-only testing, replace that one reference with a pushed
generator development branch or full commit SHA.

After selecting a usable generator ref, push the consumer integration branch and inspect the preview
artifact and enable Actions PR-creation permissions to
receive review PR updates against `Code-Documentations`. Nothing auto-merges or
publishes Pages/wiki content. The manual Run workflow button requires the caller
on the default branch; use branch pushes during this review phase. See
[shared automation](shared-pr-automation.md) for the full flow.

The eventual destination is `opensourcetransportation/atspm`. Move the reviewed
integration changes to a development branch there, confirm its source/map coverage,
and rerun generation in that repository. Source links are derived from the calling
repository and commit, so today's references correctly point at the Avenue source.
They are not rewritten to upstream before those sources exist there. Snapshot
provenance likewise retains the repository where each state was recorded.

Retiring or disabling legacy workflows on other branches/repositories requires
their own reviewed rollout; this change does not remotely alter them.
