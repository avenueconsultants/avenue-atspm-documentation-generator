## Generated configuration and log reference

The [generated documentation](docs/autogenerated/index.md) includes the
[configuration reference](docs/autogenerated/data-downloader.md),
[structured log events](docs/autogenerated/log-messages.md), and
[configuration change report](docs/autogenerated/configuration-changes.md).
These files belong to this repository and should be reviewed with source changes.

`documentation.json` registers the application source folder,
structured logging folder, branding and illustrative examples. Its automatic page
includes new annotated configuration sections and settings without maintaining a
list of every property. Keep descriptions in the C# XML comments. Unannotated types
can be registered through `configurationTypes` when needed.

The **Update generated documentation** workflow uses shared tooling from
`avenueconsultants/avenue-atspm-documentation-generator`. It scans source, checks
coverage, compares against the committed snapshot, and validates the site before
proposing updates. It does not compile/run this application or contact its APIs.
Generation never copies deployed settings or API keys; the map contains only
illustrative values. Retain the snapshot and hidden ownership manifest alongside
the Markdown, and edit source comments/the map instead of generated pages.

During rollout the workflow runs on `documentation-integration` and targets that
same branch. It follows generator `main` after the shared workflow is merged;
for branch-only testing, replace its one `@main` with a pushed branch or SHA. The caller has
`create-pr: true`; inspect the `documentation-preview` artifact and review PR.
Repository Actions settings must allow PR
creation. Pushes work on the development branch; manual dispatch requires the
workflow to exist on the repository's default branch. Nothing merges or publishes
the site automatically.

### Reading configuration requirements

The reference's **Required** column reports C# `required` and `[Required]`
annotations. It is not a complete runtime validation specification.
[HostBootstrapper](atspm-data-downloader/HostBootstrapper.cs) also requires non-default
start/end times with start <= end, a nonempty location list, and an absolute API
URL. `ApiUrl` has no required annotation, but host validation still requires it.
The API may require an API key even though the local property is optional.

The **Default** column is the property's source initializer. `OutputPath` has no
initializer, while the downloader falls back to its current working directory
when no path is provided. Supplied command-line options override bound settings;
environment settings override appsettings. For list binding use indexed variables
such as `DownloaderConfiguration__LocationIdentifiers__0` and `__1`, as shown in
the generated reference. Example JSON is illustrative, not a ready deployment file.

Structured log documentation covers this repository's `[LoggerMessage]`
declarations, not every message emitted by .NET or dependencies. The first
configuration snapshot establishes a baseline; later changes produce comparisons.
