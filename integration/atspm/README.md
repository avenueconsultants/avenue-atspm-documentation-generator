## Maintaining the reference

`documentation.json` owns the source folders, service mappings,
branding and example values. Source XML comments supply setting descriptions.
New properties of mapped sections appear automatically. For a new section, add
its name to each service that consumes it. The coverage check fails for unmapped
sections rather than guessing which services need them. Add new source roots to
`sourcePaths` when definitions live outside the configured folders.

Keep the four database context bindings explicit: `ConfigContext`,
`AggregationContext`, `EventLogContext`, and `IdentityContext`. Their environment
variable names follow the actual named bindings. Preserve the reviewed duplicate
event-ID allowlist; investigate any new duplicate before allowing it.

The shared generator parses source without running ATSPM. Required flags and
defaults describe supported annotations and source initializers, not the complete
runtime validation rules or deployed values. The API documentation models in
`Atspm/Infrastructure/Configuration/Documentation/ApiConfigurationSections.cs`
remain part of the source input; changes to runtime authentication binding should
also be reflected in those models. Dependency-only settings and source outside the
configured folders are not automatically discovered.

Generated examples contain placeholders and are not deployment configuration.
Keep the snapshot and hidden ownership manifest with the pages. The first snapshot
establishes a baseline; subsequent runs expose changes for developer/cloud review.
Edit source comments or the map rather than editing generated files.

## Development workflow

`.github/workflows/update-autogenerated-docs.yml` is the sole documentation
generation workflow. It calls shared automation from
`avenueconsultants/avenue-atspm-documentation-generator`. The obsolete
`generate-docs.yml` workflow, which attempted to replace `Code-Documentations`
with an orphan output branch, has been removed in this integration change.

Both source and PR target are `Code-Documentations`. Pushes to that branch rebuild
the documentation; documentation-only changes are ignored. The shared workflow
validates in staging and uploads a preview before proposing any changes. After
activation, it maintains one reviewable documentation PR and never merges it or deploys
Pages/wiki content.

**Activation is pending the shared workflow on generator `main`.** For an earlier
branch-only run, replace its one `@main` reference with a pushed generator
branch or full commit SHA. The caller has `create-pr: true`; inspect its
artifact and PR before merging. Enable Actions PR creation in repository
settings. The manual-dispatch button requires the workflow on the default branch;
use branch pushes for testing without merging to main.

This integration is developed in `avenueconsultants/udot-atspm-development`.
Its eventual home is `opensourcetransportation/atspm`. The workflow derives source
links from the calling repository and exact source commit, so it does not falsely
link development code to upstream. When moving upstream, retain the integration
branch and rerun there to refresh provenance before reviewing the output. No
production branch switch, merge or publication is automatic.
