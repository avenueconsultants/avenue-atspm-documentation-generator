## Reproduce the regression comparison

Obtain a clean source checkout at the exact source commit above. For this workspace:

```powershell
dotnet build GenerateDocuments.sln --configuration Release
python scripts/check_baseline.py --source-root _source/baseline-atspm
python scripts/validate_repository.py
```

The comparison uses the current Release generator with the frozen map and source
revision. It rejects a different revision or dirty source checkout and generates
into a temporary directory. Since Part 5 it checks the seven original service/log
pages byte for byte, verifies the exact added index link and manifest entries, and
validates the two new snapshot/report files. The generated manifest now uses LF
line endings on all platforms. Original fixtures are not rewritten; these are
explicit compatibility assertions. Rebuild after changing generator code.

For a site preview, generate current output from that source checkout first (the
frozen Part 1 fixture intentionally does not contain the new report page):

```powershell
dotnet src/GenerateDocuments/bin/Release/net8.0/AtspmDocsGenerator.dll `
  --workspace-root . --source-root _source/baseline-atspm `
  --output-root _generated/baseline-atspm --map config/container-config-map.json `
  --repository-url https://github.com/avenueconsultants/udot-atspm-development `
  --repository-ref 82bc9983533671a00d92532289c438e54a5f60e5 `
  --generated-at 2026-09-29T10:54:25-06:00
$env:DOCS_CONFIG = (Resolve-Path config/container-config-map.json).Path
$env:DOCS_DIR = (Resolve-Path _generated/baseline-atspm).Path
python -m mkdocs build --strict --site-dir _generated/baseline-site
```

Do not casually refresh the snapshots to make a failing comparison pass. Review
intentional output changes and their compatibility implications first.

## Existing integration findings

At the pinned source commit, both documentation workflows are still present:

1. `.github/workflows/update-autogenerated-docs.yml` calls
   `avenueconsultants/atspm-documentation-generator@7d71ac2d56309d31b14f239d7d9b0dd604568569`.
   It scans the caller checkout. Push triggers and PR base are hardcoded to `main`;
   it also supports manual invocation and PR validation. It is not yet configured
   to target the development branch for generated-documentation PRs.
2. `.github/workflows/generate-docs.yml` now triggers on pushes to `main`. It checks
   out an unpinned generator, sets up .NET 7, guesses an entry point, suppresses a
   `dotnet run` failure, and attempts an orphan-branch force-push to
   `Code-Documentations`. This conflicts with using that branch for source development.
   Retire it in the later reviewed ATSPM integration change; do not run it for testing.

This generator's own CI currently reads upstream `opensourcetransportation/atspm`
at moving `main`. That integration check is distinct from this pinned development
baseline and has not been changed in Part 1. The consumer action namespace also
differs from this repository's documented upstream namespace; settle the canonical
published generator location during the workflow integration part.
